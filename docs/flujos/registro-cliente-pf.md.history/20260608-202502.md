# Flujo: Registro de Cliente — Persona Física

## Resumen

Captura y validación de datos para el registro de un cliente persona física en el sistema PLD. Cubre dos rutas según la nacionalidad (Mexicano o Extranjero), cada una con una bifurcación adicional según la modalidad de acude (por su cuenta o con representante legal). Cada sección de captura sigue el patrón: ingresar datos → validar → guardar o corregir.

## Actores

- **Operador** — ejecuta la captura de datos en cada paso del formulario.
- **Sistema** — valida los datos ingresados, solicita correcciones y persiste la información.

## Precondiciones

- Existe un contexto de registro activo (draft o en progreso).
- El tipo de persona ya fue seleccionado como **Persona Física**.

## Patrón de validación por sección

Cada sección de captura sigue este ciclo interno (no representado en el toon principal para mantener legibilidad):

```
[Captura sección] → ¿campos completos?
                       ↓ Sí → Guardar información
                       ↓ No → Ingresar dato faltante → (repite)
```

## Bifurcaciones principales

| Decisión (label en el toon) | Rama A | Rama B |
|---|---|---|
| ¿Cuál es su nacionalidad? | Mexicano → domicilio particular + identificación nacional | Extranjero → pasaporte + doc INM + domicilio en territorio nacional |
| ¿Bajo qué modalidad acude? | Acude por su cuenta → pasa directo a beneficiario controlador | Acude con su representante legal → captura datos del representante antes de beneficiario controlador |
| ¿Es PEP (titular)? | Sí → registrar cargo | No → revisar parentesco/cónyuge |
| ¿Tiene parentesco o es cónyuge de una PEP? | Sí → registrar cargo y nombre completo de la PEP | No → (sin arista definida en el toon — pendiente de aclarar) |
| ¿Los campos están completos? (validación) | Sí → guardar información | No → usuario regresa al formulario |
